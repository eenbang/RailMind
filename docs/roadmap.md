# RailMind 迭代路线

## M0：框架与契约

- 固定目录、领域模型、API 契约
- 接入上海到杭州样例数据
- 建立权重评分器和规则型意图解析
- 提供前端信息架构与模块占位

退出条件：前后端可以分别替换数据、解析器和评分器，而不影响其他模块。

## M1：可演示闭环

- 完成传统表单和偏好控制台
- 返回 Top 3、分项得分和推荐理由
- 完成方案比较和空结果恢复
- 加入基础响应式设计

退出条件：用户能完成“输入条件 → 看推荐 → 调偏好 → 比较方案”的完整路径。

## M2：自然语言体验

- 完善中文时间、车站、价格和座位表达
- 增加追问状态机
- 接入结构化输出 LLM，保留规则回退
- 建立解析测试集与错误统计

退出条件：常见自然语言输入的成功解析率达到预先约定阈值，失败时可平滑回到表单。

## M3：正式数据层

- SQLite 表结构、批量导入和查询索引
- 数据版本与导入校验
- 增加线路覆盖和日期维度
- 评估实时余票接口

退出条件：更换线路不需要改业务服务，数据缺陷可定位、可回滚。

## M4：高级规划

- 中转方案生成与比较
- 预算、到达时间和舒适性的组合提示
- 可选的用户偏好保存
- 购票平台深链

## 工程护栏

- 每次评分规则变化更新 `ALGORITHM_VERSION`。
- 每次数据导入生成 `data_version`。
- 推荐排序必须有单元测试和固定样例。
- LLM 输出先通过 Schema 校验，再进入领域对象。
- 新增字段先进入契约文档，再同时更新前后端类型。
